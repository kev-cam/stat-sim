# The AN-2597 radio link in simulation: AD9361s driven from software

This directory simulates the drone-to-controller radio link of Analog Devices' application note
AN-2597, "An OFDM-Based HDL Reference Modem Using the AD936x RF Transceivers" (the ADSW-OFDMS2M
reference modem on the ADRV9361-Z7035).  Each end is a behavioural model of the AD9361 built from
its published specifications; the OFDM modem is software, not HDL, and hands samples to the chip
model through the same controls a program uses on the real part under Linux IIO.

The point is the RF path -- what the transceiver and the air do to a waveform -- at a cost low
enough to simulate whole systems: links first, then arrays of many channels.

**Read this first**

- This is not an Analog Devices document and is not endorsed by Analog Devices.  AD9361, AD936x,
  ADRV9361-Z7035 and ADSW-OFDMS2M are ADI's products and names.
- The model was written from published specification values.  No ADI source code, HDL or register
  data was used.  It has not been compared with hardware.
- AN-2597 and the AD9361 data sheet PDF could not be opened from the machine this was written on

## What is here, against what AN-2597 describes

| | ADSW-OFDMS2M (ADI wiki page) | this simulation |
|---|---|---|
| Hardware | ADRV9361-Z7035 (AD9361 + Zynq-7035) at each end; also ZedBoard + AD-FMCOMMS3-EBZ | two AD9361 behavioural models; no FPGA; no board RF (baluns, matching, filters); an ideal external PA and LNA can be added |
| Bands | 2.412 to 2.462 GHz, 5.180 to 5.240 GHz | any LO the chip tunes; results below at 2.437 GHz and 5.200 GHz |
| Channel widths | 5, 10, 20 MHz | 5, 10, 20 MHz (sample rate = channel width, RF bandwidth 0.9 of it) |
| Waveform | modified IEEE 802.11n, HT-mixed preamble | 802.11a/g numerology: 64-point FFT, 52 used subcarriers (48 data, 4 pilots), 1/4 guard, two short and two long training symbols |
| Modulation | BPSK, QPSK, 16-QAM, 64-QAM | the same four |
| Coding | convolutional, rates 1/2, 3/4, 5/6, Viterbi decoder | none: the measures are EVM and uncoded bit error rate |
| Antennas | 1T1R SISO; 2T2R spatial diversity (STBC, cyclic delay, MRC) | 1T1R |
| PHY rate | 54 Mbps SISO, 65 Mbps MIMO | not applicable (no coding, no MAC) |
| Application | drone sends video, controller sends telemetry; Kuiper Linux | the drone sends packets while it flies out along a line; the controller receives them |
| Modem | HDL in the FPGA | software: `ofdm.py` (Python), `ofdm_soft_pkg.vhd` (VHDL processes, no RTL) |

So this reproduces the link's radio conditions (carrier, bandwidth, modulation, the transceiver's
impairments, free space, a carrier offset between the two references, a burst AGC) and not the
modem's own design.  What it reports is what the transceivers and the path leave of the signal:
EVM at the receiver's data port against distance, for each modulation.

## The AD9361 model

Modelled at the data port, per sample (`ad9361.py`; the same numbers and arithmetic in VHDL,
`ad9361_pkg.vhd`):

- **Transmit:** 12-bit DAC word, analog baseband filter, attenuator in 0.25 dB steps, third-order
  compression set by OIP3, carrier leakage (the data sheet's 0 dB and 40 dB attenuation points),
  output noise floor, LO phase noise, and a residual error that brings the EVM to the data sheet's.
- **Receive:** noise figure, third-order compression (input intercept rising as gain falls), analog
  baseband filter, quadrature gain and phase error, gain in 1 dB steps, 12-bit ADC with clipping,
  the same EVM treatment, LO leakage out of the RX port.
- **Gain control:** manual, slow attack, and a fast-attack burst AGC (acquire on energy or
  overload, settle to a target level, re-acquire on a stronger signal, release when energy is lost).
- **Controls:** pyadi-iio's names -- `rx_lo`, `tx_lo`, `sample_rate`, `rx_rf_bandwidth`,
  `tx_rf_bandwidth`, `gain_control_mode_chan0`, `rx_hardwaregain_chan0`, `tx_hardwaregain_chan0`,
  `tx()`, `rx()`.  A reference clock error in ppm moves both LOs.

Not modelled: the SPI register map, the digital FIR and half-band filters, the data-port timing,
calibrations and tracking loops (the model has the residual errors, not the loops), TDD switching
times, sample-clock offset, temperature.

The settings used for the link, in IIO terms:

| control | drone | controller |
|---|---|---|
| `rx_lo`, `tx_lo` | 2437000000 | 2437000000 |
| `sample_rate` | 20000000 | 20000000 |
| `rx_rf_bandwidth`, `tx_rf_bandwidth` | 18000000 | 18000000 |
| `gain_control_mode_chan0` | (transmitting) | `fast_attack` |
| `tx_hardwaregain_chan0` | 0 dB (full power) | (receiving) |
| reference error | +1.0 ppm | -1.5 ppm (6.1 kHz between the carriers) |

Packets are sent 12 dB under DAC full scale (-4.5 dBm average at the TX port; a full-scale tone is
7.5 dBm).  Antennas are 2 dBi.  Receiver noise in the 20 MHz band is -98.0 dBm (NF 3.0 dB).

What the data sheet gives only as plots, or not at all, is the model's own assumption:

- **Noise figure and IIP3 against gain:** NF is held at its maximum-gain value at every gain; IIP3
  rises 1 dB for each dB the gain is reduced, up to +20 dBm.
- **Analog filter corners against RF bandwidth:** RX baseband low-pass at 1.4 x half the RF
  bandwidth with a TIA pole at 2.5 x; TX baseband low-pass at 1.6 x with a second pole at 5 x.
- **Transmit compression** follows the attenuator (the attenuator is before the compressing stage).
- **LO phase noise** is a first-order process with a 100 kHz corner and the rms above.
- **Slow-attack AGC:** one decision per 1 ms; 1 dB steps outside -12 .. -10 dBFS, 4 dB steps
  outside -18 .. -5 dBFS.
- **Fast-attack AGC:** power measured over 16 samples; acquires above -18 dBFS or on an ADC
  overload; settles to -12 dBFS in at most four steps (12 dB down on an overload); re-acquires if the
  signal rises 9 dB or overloads; releases to maximum gain after 8 measurements 15 dB under target.

Everything is in three tables at the top of `ad9361.py` (`SPEC`, `SCALARS`, `MODEL`).  Change a
value there, run `ad9361_vhdl.py emit`, and the VHDL and the accelerator follow.

### Checks on the model

- `ad9361.py check` measures the model the way the data sheet measures the chip (two-tone
  intercepts, full-scale tone power, noise with no input, EVM of a modulated signal, carrier
  leakage) at 800 MHz, 2.4 GHz and 5.5 GHz: every figure comes back within 0.2 dB of the table.
- `ad9361_vhdl.py check` runs the VHDL in the simulator against the Python: 309 values; the
  noise-free paths agree bit for bit at the ADC and to 6e-16 at the transmitter output.

## How the link is simulated

Three implementations of the same chip model run the same link:

1. **Python, time domain** (`an2597_link.py`): sample by sample, the reference.
2. **VHDL in nvc, spectral events** (`an2597_link.vhd`, run by `an2597_nvc.py`): each OFDM symbol
   period is one simulation event carrying the symbol's 64 spectral lines (complex amplitude per
   subcarrier) instead of 80 samples.  Linear parts scale the lines; the chip's non-linear parts
   (DAC and ADC words, compression, the AGC changing gain part-way through a symbol) run on the 64
   samples of that event; a carrier offset is applied exactly within the event.  Antennas are
   drivers and receivers in an "arena": each antenna receives the sum of what every other antenna
   radiates, through free space between their positions.
3. **The same VHDL design with its RF path on a GPU** (`an2597_nvc.py --accel`): the spectra and
   their processing are moved out of the simulator, one GPU thread per frequency line, and can be
   moved back at any symbol boundary.

All three use free-space propagation between antenna positions (Friis, with the carrier phase).

- At 2.437 GHz and 20 MHz all four modulations are within 0.9 dB of the budget from 1 m to 300 m.
  Uncoded bit error rate at 100 m: none seen for BPSK and QPSK, 2e-3 for 16-QAM, 4e-2 for 64-QAM.
- The Python time-domain model agrees with the VHDL within 0.5 dB up to 100 m, and the AGC settles
  at the same gains in both.  With the RF path on the GPU the results are the same within the
  scatter of 10 packets (within 1.1 dB of the budget).
- Short range is limited by the two EVM floors (-40 dB transmit, -42 dB receive at 2.4 GHz), long
  range by thermal noise; with these bare-chip powers 64-QAM without coding holds to about 30 m in a
  20 MHz channel.
- With an ideal 20 dB PA and a 15 dB, 1.5 dB-NF LNA at each end (Python, 2.437 GHz, 20 MHz): -27.6 dB
  at 300 m and -17.7 dB at 1 km.

## Speed

Two radios, 20 MSPS, one event per 4 us symbol, on a laptop (i9-12900H, RTX 3070 Ti):

| | simulated time / wall time |
|---|---|
| VHDL in nvc | 0.008 |
| VHDL in nvc, RF path on the GPU | 0.048 |
| Python, time domain | 0.07 to 0.12 |
| standalone GPU program taking thousands of symbols per launch (`gpu/`) | 18 to 47 |

The GPU work is aimed at arrays rather than at this two-radio link: a phased-array radar of 64
transmit and 64 receive AD9361 channels with moving targets (`phased_radar.vhd`) takes 71 ms per
pulse in the simulator alone and 1.7 ms with its RF path on the GPU.  See `../README.md`.

## Running it

Python only (numpy and scipy; no simulator):

    python3 ad9361.py spec                       the numbers and where each came from
    python3 ad9361.py check                      the model measured as the data sheet measures the chip
    python3 an2597_link.py                       the link at 2.437 GHz, 20 MHz
    python3 an2597_link.py --lo 5.2e9 --fs 10e6  5.2 GHz band, 10 MHz channel
    python3 an2597_link.py --pa 20 --lna 15 --lna-nf 1.5

The model from a program, with pyadi-iio's names:

```python
import numpy as np
from ad9361 import AD9361, Arena

def radio(name, seed):
    sdr = AD9361(name, seed=seed)
    sdr.rx_lo = sdr.tx_lo = 2437000000
    sdr.sample_rate = 20000000
    sdr.rx_rf_bandwidth = sdr.tx_rf_bandwidth = 18000000
    sdr.gain_control_mode_chan0 = "fast_attack"
    sdr.tx_hardwaregain_chan0 = 0                 # dB; 0 is full power
    return sdr

drone, ctrl = radio("drone", 1), radio("controller", 2)
air = Arena()                                     # free space between the two
air.add(drone, (0, 0, 0), antenna_gain_dbi=2)
air.add(ctrl, (30, 0, 0), antenna_gain_dbi=2)     # 30 m away

n = np.arange(4096)
drone.tx(2**13 * np.exp(2j * np.pi * 1e6 / 20e6 * n))      # a 1 MHz tone, 12 dB under DAC full scale
ctrl.rx_buffer_size = 4096
iq = ctrl.rx()
print(ctrl.rx_hardwaregain_chan0)                 # 63.9: where the fast AGC settled
print(10 * np.log10(np.mean(abs(iq[2048:]) ** 2) / 2048 ** 2))   # -11.7 dBFS at the ADC
```

VHDL: needs nvc built from the kev-cam/nvc fork (its `--std=2040` spectral mode and `rf` library).

    python3 an2597_nvc.py --nvc <path to nvc> --compare     the link in nvc beside the Python model
    python3 an2597_nvc.py --nvc <path to nvc> --accel       RF path on the GPU (build accel/ first; CUDA)

## Limits

- Free space only: no multipath, no fading, no interference from other users of the band.
- Propagation delay is a phase on each subcarrier, not a delay of the symbol (fine while the delay
  is shorter than the guard interval).
- One transmit and one receive channel per chip in the VHDL (the Python model has both channels and
  the isolation between them).
- The reference error moves the LOs only; the sample clocks are taken as equal.
- No coding, so no packet error rate, sensitivity or throughput figures to set beside AN-2597's.
- The fast-attack AGC is a plausible burst AGC, not the AD9361's state machine register for register.

## Questions for ADI

Numbers the model uses from memory, where a correct value would replace a guess:

1. Integrated LO phase noise per band (0.13 / 0.37 / 0.59 degrees rms at 800 MHz / 2.4 GHz / 5.5 GHz),
   and a reasonable spectral shape for it.
2. TX EVM at 5.5 GHz (-36 dB) and carrier leakage at 40 dB attenuation at 5.5 GHz (-30 dBc).
3. The data-port sample rate limits.

Behaviour the data sheet does not tabulate, where the model has its own assumption:

4. How noise figure and IIP3 move with the gain index across the gain table (the model keeps NF
   constant and trades IIP3 dB for dB with gain).
5. The analog baseband filter corners as a function of the RF bandwidth setting.
6. CW input power for ADC full scale against gain (the model has +5.9 dBm at 0 dB gain).
7. Whether transmit linearity (OIP3) follows the attenuator setting dB for dB.

About the reference design itself, which could not be read here:

8. How ADSW-OFDMS2M sets the AD9361 for each channel width: sample rate, RF bandwidth, FIR, gain
   control mode and its thresholds, transmit attenuation, TDD or FDD.
9. The reference accuracy to assume for the ADRV9361-Z7035's oscillator.
10. Measured EVM, sensitivity or range for the design, to set beside the tables above.
